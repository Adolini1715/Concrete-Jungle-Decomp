# Decomp tools added 2026-10-25

## Typed Ghidra drafts (`tools/typed_drafts.sh`)
Ghidra drafts used to print every object as `void *this` and every field as `*(int *)(this + 0x2c)`.
The typed pass gives Ghidra our layouts first:

1. `tools/offsets_probe.py` compiles every header with VC7.1 (private/protected opened up) and reads
   `sizeof` / `offsetof` of every data member from the object: `build/field_offsets.json`
   (762 classes, ~5,500 members). `--lint` compares with the `// 0x..` comments (0 mismatches on
   2026-10-25).
2. `tools/ghidra_types.py` turns headers + probe into `build/ghidra_types.txt`: structures (flattened
   over the base chain), field types (builtins, pointers to known classes, embedded classes, arrays),
   `this` classes for ~9,000 methods, types for ~940 globals.
3. `tools/ghidra/PcjTypes.java` applies them (`VariableUtilities.findOrCreateClassStruct`, so the
   auto `this` parameter picks them up); `PcjDecomp.java` decompiles; `tools/drafts.py` (now with
   `PCJ_DRAFT_RAW` / `PCJ_DRAFT_OUT` and hash names inline) writes `build/drafts-typed/<unit>.c`.

Result: `this->m_Text`, `this->m_pItem->m_position.x`, `gpPlayerItem[0]->m_position`, ... Unknown
regions show as the header's `m_UnkXX` byte arrays, which is itself a pointer to what to name next.
Ghidra lives in /home/claude/ghidra (11.2.1), project in /home/claude/ghidra-pkg/proj.
`typed_drafts.sh import` rebuilds the project from scratch (~40 min analysis).

## `tools/brief.py NAME|VA`
Everything to write one function: signature/status, typed draft, callees with status, globals with
types, most similar written functions (templates), and prototype asserts for the same source file.

## `tools/clones.py`
`scan` / `report` / `families` / `near VA`. Normalised instruction streams of every function: finds
unwritten functions that are copies (same code and callees, or same shape) of written ones, families
of unwritten clones, and the nearest written function to start from. Finding on 2026-10-25: only ~24 KB
of the 1.3 MB unwritten is clones (mostly header inlines that appear once their callers are written).

## `docs/aug04_asserts.txt`
The 242 `ASSERT` expressions of the August 2004 prototype XBE, tagged with the nearest source-file
string: original member, local and macro names (`POI_MAX_LIST`, `DelaySpawnCount`, `SM_RegWords`...).
